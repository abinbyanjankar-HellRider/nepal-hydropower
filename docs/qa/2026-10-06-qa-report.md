# QA report: Nepal hydropower platform, 2026-10-06

Scope: data integrity, calculations, logic loopholes, security basics, performance and test coverage across the
whole project (the income/finance modules added on 2026-10-05 and the older code). Method: read-only queries
against `data/projects.db`, the Flask test client, a coverage run, and an independent code review of the older
modules. Every finding below was reproduced, not guessed. Details of the older-code review are in
`2026-10-06-legacy-code-review.md`.

Project state files (`.10x/`) were not created: the skill's discovery step was skipped because this session already
holds the project context. Nothing here has been committed.

## Verdict

The numbers the new pages show are internally consistent and the calculation core is well tested. The weakest part
is not the maths but the **data-merge layer** (`src/collectors/sync.py`, name cleaning) which has already damaged
real records, plus a handful of duplicate projects that inflate capacity totals. Fix those first.

## Evidence that things are sound

- 145 tests pass; the analytics core is 95-100% covered (`income.py`, `finance_cost.py`, `technical.py`,
  `company_trends.py`); `dashboard.py` 94%, `sync.py` 95%, overall 75%.
- No orphaned foreign keys, no duplicate stock symbols, no listed company without a symbol, no operating plant with
  missing or zero capacity or missing commissioning year.
- Reported EPS equals net profit / (paid-up capital / 100) for all 105 companies checked; book value per share
  equals (paid-up + reserves) / shares for all 105. No verified PPA fact is duplicated, none has wet above dry, none
  is outside NPR 2-12.
- Unit conversions (NPR vs NPR million, GWh vs kWh), Excel cell references and Bikram Sambat to AD conversion
  were checked and are correct.
- Defaults are safe: the dashboard binds to 127.0.0.1, debug is off, the one write endpoint needs a constant-time
  checked admin token, and every new query parameter rejects nan/inf/out-of-range input with HTTP 400.
- Speed is fine: every endpoint answers in under 0.7 s except the Excel export (3.3 s).

## Critical

**C1. The project matcher overwrites real projects (already happened twice).**
`src/collectors/sync.py:107` and `:200-207`. A project matched to a generation licence can be matched again by a
later survey-licence row, which then overwrites its name, capacity, licence, dates and developer. Verified: the raw
DoED files contain `Sabha Khola A` (10.4 MW, licence 128, Deepsabha Hydropower) and `Sani Bheri HEP` (44.52 MW,
licence 389, Expert Hydro). The database has no project with licence 128 or 389; they survive only as `HP_243`
(9 MW, survey licence 1282) and `HP_367` (45 MW, survey licence 1457) with different developers. The record flips on
every full sync. Fix: an authoritative stage must not overwrite a project that came from a higher stage unless the
licence number or promoter agrees. Then repair the two rows from the raw files. Add a regression test.

## Important (data and logic)

1. **Duplicate projects inflate totals.** Same project under two names: Kulekhani III (`HP_046` and `HP_758`, both
   OPERATIONAL 14 MW), Myagdi Khola-B (`HP_456` and `HP_815`, 12.5 MW), Budhigandaki (`HP_019` and `HP_739`,
   1,200 MW each, PLANNED, different districts), probably `HP_824`/`HP_450`. Operating capacity (4,010 MW) and
   planned capacity (27,960 MW) are overstated. A fuzzy scan (same district, capacity within 2%, similar name) found
   33 candidate pairs; most are genuinely different "Upper/Super" projects, so each needs a human check.
2. **Cross-district merging.** Same name and capacity merge even when districts differ; a record with no capacity
   matches any same-named project (`sync.py:125-128`, `:47-50`).
3. **Re-sync overwrites corrections.** A DoED re-sync replaces hand-corrected values and resets their reliability tag
   to "doed" (`sync.py:206-211`).
4. **Name folding.** "Budhi Gandaki Ka" and "Kha" fold to the same name; "11" folds to "1" (`cleaners.py:50-51`).
5. **Company names cut at "and"/"&".** 19 promoters are truncated, e.g. Upper Trishuli-1's developer is stored as
   "Nepal Water" (`cleaners.py:90`).
6. **Spacing splits companies.** "Nilgirikhola" and "Nilgiri Khola" are two company records (`cleaners.py:94-97`).
7. **Stale "latest" quarter.** IHL's headline shows a Q3 profit while its Q4 is a loss.
8. **Tax credits shown as tax holidays.** A negative tax provision displays as "Tax-free (holiday)" for AKPL, DORDI, CHL.
9. **Negative debt-to-equity.** MCHL has negative equity and shows -8.43, so it ranks as least indebted.
10. **Arbitrary headline PPA rate.** For companies with several plants the profile shows whichever plant's fact was
    stored first, not the latest as the docstring says.
11. **Copied coordinates.** The location filler gave 7 projects the exact coordinates of a different same-named plant.
12. **Two revenue models disagree.** `projects.ppa_rate_npr_per_kwh` is empty for every project, so the older
    `analyze revenue` command and the Excel "Revenue estimate" sheet price every plant at the assumed 4.80/8.40
    tariff and ignore the 94 companies' verified PPA rates. The new `/income` page uses the verified rates. The two
    now give different answers for the same plant.

## Important (new income and finance model: known limits, not bugs)

- **Calibration hides data problems.** 7 of 90 calibrated companies are clipped (raw factors 3.11, 2.44, 1.98, 1.87,
  1.72, 0.20, 0.10). Joshi (0.10) and HDHPC (0.20, flood-damaged Mai Cascade) look like plants not producing;
  Chhyangdi, BHDC, Makar, HURJA and CHCL look like a wrong or missing capacity or tariff. The page shows only the
  clipped factor, so a reviewer cannot see the raw one.
- **Usage percentages for 16 companies (310 MW of 2,205 MW) rest on an assumed tariff.** Calibration scales energy
  and income together, so a wrong fallback tariff is absorbed into the usage figure. CHCL is the clearest case: its
  PPA is a flat rate near NPR 8.17, far above the 4.80/8.40 seasonal fallback.
- **Seasonality is assumed, not measured.** Every company gets the same 30% dry-season energy share. Profit-shape
  agreement is loose (median gap 13.8 percentage points on 28 companies; profit is more seasonal than income, so
  this is expected but unvalidated).
- **Growth is not modelled.** 13 plants (2,724 MW, including Arun 3 at 900 MW) have an expected completion of 2027 or
  earlier; the forecast counts operating plants only, so FY 2083/84 income is understated for companies about to
  commission.
- **Tax holidays are not modelled.** 22 companies have tax-holiday mentions; the scenario holds today's effective tax
  rate for five years, so after-tax gains are overstated where a holiday ends.
- **Implied interest rate is approximate.** Loans are year-end, "loans and long-term liabilities" may include
  non-interest-bearing items, 8 companies are outside 2-20%, and 5 report loans with zero finance cost.
- **Parent and subsidiary overlap.** Listed groups (for example Chilime and Sanjen) may be double counted in the
  portfolio totals when sales are consolidated.

## Minor

- The Excel export writes any cell starting with `=`, `+`, `-` or `@` as a formula. No such value exists in the data
  today, but names come from scraped sources, so this is latent formula injection.
- IRR and payback helpers are wrong above 100% IRR and when there are construction years; unknown revenue is summed
  as 0; a year with zero energy gives an infinite tariff.
- The coordinate parser accepts 75 minutes and loses some formats; the duplicate check compares each name group only to
  its first member; a placeholder licence `1_gtd` is shared by 12 NEA plants; `HP_763` has commissioning year 1934
  (check); five exact duplicate project names exist (most are distinct phases).
- Coverage gaps: CLI and scraper modules sit at 22-48% (`web_scraper.py` 22%, `cli_reports.py` 36%, `cli_analyze.py`
  41%, `cli.py` 41%, `company_reports.py` 48%). Network code is hard to unit test; add recorded-fixture tests for the
  parsers.

## Recommended order of work

1. **Fix the matcher (C1, items 2-4) with regression tests, then repair `HP_243`/`HP_367`.** Highest risk: it silently
   corrupts the source of truth on every sync.
2. **Merge the confirmed duplicates** (Kulekhani III, Myagdi Khola-B, Budhigandaki; verify the rest) and add a
   duplicate guard to the merge step. Back up first.
3. **Make the old revenue estimate use verified PPA rates** (fill the project rate from `company_facts`, or call
   `income.forecast`) so the Excel sheet and the dashboard agree.
4. **Show the raw calibration factor** and add a "check data" list for clipped companies; add a manual capacity
   override path so Chhyangdi, BHDC, Makar, HURJA, CHCL and Joshi can be corrected with a source.
5. **Repair company names** (19 truncated promoters, spacing duplicates) and fix the debt-to-equity and tax-holiday
   labels.
6. **Model upcoming commissioning** (add plants with an expected completion in the horizon, flagged as projected)
   and tax-holiday expiry, if forecast accuracy matters.
7. **Escape formula-leading cells in the Excel export** (prefix with an apostrophe) and add parser tests.
